# ADR 0016 — The project's documentation and an inventory of features drawn from the tests

| | |
|---|---|
| Status | **Accepted** (17 October 2026). Implemented in one delivery |
| Backlog item | 9.11 — the project's documentation |
| Decided by | the owner of the branch, away during the session, who asked for the recommended option on every point of section 4 |

## 1. Context

The documents grew one item at a time: a user guide, an operator's README, a developer guide, a list of features with
the commits that brought them, fourteen ADRs. Nothing tied a feature to the proof that it works, and nothing showed the
whole of what the software does — every search and filter, the search by EPC included — in one place. The owner asked
for every document and manual reviewed and completed, with an inventory of every feature drawn from the development
tests' checks, so that each feature names the checks that prove it.

The development tests are about 50 programs printing one `PASS <check>` line per check, about 3,900 in all; each check's
name is a sentence that says what is true (*a reader (limit 0) may not export records: 403 export.notAllowed*). Those
sentences are already the most complete and the most current description of the software.

## 2. Decision

1. **The inventory is generated from a run of the tests**: `DEV_TESTS_INVENTORY=<folder>` makes the pytest layer keep
   each program's `PASS` lines; `python dev-tests/docs/inventory.py build <folder>` writes
   `Documentation/test-inventory.md` — every check of every program, grouped by area and program, with counts — and
   `Documentation/test-inventory.json`, the same for the tests to read. It is regenerated by the delivery that changes
   the checks (as the guide's screenshots are), from a complete strict run; the CI-only program on a real MongoDB is
   listed with its count only.
2. **Every feature cites the checks that prove it**: each row of `Documentation/features.md` gains a *Checks* column
   with one or more references `program` or `program: words`, where the words are found in a check's name of that
   program. A test (`dev-tests/docs/test_docs.py`) fails when a feature cites nothing, when a reference names no
   program or matches no check, and when a program of `dev-tests/test_programs.py` is missing from the inventory.
3. **The same test keeps the documents in step**: every count of `developer-guide.md` section 13 equals the inventory's
   for that program; the API reference equals what `portal/openapi.json` gives (below).
4. **Manuals by reader**, each reviewed against the software and completed:
   - users — `portal-user-guide.md` (the editor, records, searching and filtering, labels and EPC, requests, overview);
   - organisations' administrators — the same guide's administration sections, gathered under one heading;
   - operators — `extensions/README.md` (installation, configuration, operation, going to production);
   - developers — `developer-guide.md`, the ADRs, `dev-tests/README.md`;
   - integrators — **`api-reference.md`**, generated from `portal/openapi.json` by `portal/tools/gen_api_reference.py`
     (every operation, parameter, answer and message code of `/portal/api/v1`).
   `Documentation/README.md` becomes the index by reader.
5. **British English only**, as `CLAUDE.md` says; manuals in Portuguese are left for the owner to ask for.

## 3. Design

- `dev-tests/test_programs.py`: with `DEV_TESTS_INVENTORY` set, each program's `PASS` lines are written to
  `<folder>/<program>.txt`.
- `dev-tests/docs/inventory.py`: `build <folder>` (the markdown and the JSON; areas from a fixed map of programs);
  `AREAS` names the areas in the order of the user guide.
- `dev-tests/docs/test_docs.py` (group `portal`, no network): the checks of decisions 2 and 3, and the API reference.
- `portal/tools/gen_api_reference.py [--check]`.

## 4. Options considered

| Point | Chosen (recommended) | Not chosen |
|---|---|---|
| Source of the inventory | the `PASS` lines of a test run | the check names read from the sources (f-strings, loops: incomplete); a list written by hand (drifts) |
| Where a feature's proof is named | a *Checks* column in `features.md`, verified | a separate mapping file (two places to keep together) |
| API reference | generated from `openapi.json` | written by hand (drifts from the description the API serves) |
| Manuals in Portuguese | not now (the owner may ask) | written now (twice the text to keep in step) |

## 5. Consequences

- A delivery that adds, renames or removes checks regenerates the inventory and the developer guide's counts; the test
  says so when it is forgotten.
- A new feature row in `features.md` needs at least one reference to a check.

## 6. Delivery

This record; the inventory and its tools; `features.md` with its *Checks* column; `api-reference.md`; the manuals
reviewed; the documentation index; `test_docs.py`.
