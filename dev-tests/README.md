# Development tests

All run without Docker or MongoDB and exit with status 1 on any failure. Run them from the
repository root.

| Test | What it exercises | How to run |
|---|---|---|
| `resolver/test_resolver.py` | The **web and data entry code** of this repository (real data-entry authoring + real web server through Flask's test client): hierarchy walk-up (a serial-number record before a batch record; informative qualifiers ignored and kept out of the linkset), linkType forms, 404 rules, the choice of a link (examples 5 to 13 of the standard, 300 as a linkset), the query string passed on exactly as sent, `%2F` in values, request paths refused by the engine, `/eh…` and `/ex…` EPC binary strings (decompressed form, linkset, data attributes passed on, 400s), linkset schema validation, JSON-LD, HTML pages and language choice, the resolver description file built from the environment, the data entry summary, resolution of one record per primary key and of qualified records of every key, walk-up through variant and batch (with the real GS1 Syntax Engine when `GS1_SYNTAX_ENGINE` is set), plus the upstream `tests/setup_test.py` expectations. | `pip install -r web_server/src/requirements.txt jsonschema`, then `python dev-tests/resolver/test_resolver.py` |
| `resolver/test_epc_binary.py` | The **EPC binary decoder** (`web_server/src/epc_binary.py`, item 1.6): the two worked examples of the Compression Technical Standard for EPC binary strings, every vector of TDS 2.3 annex E.3 (also the `++` schemes and, with corrected headers, the SSCC++ and ITIP++ examples of erratum E9) in `eh` and `ex` form, +AIDC data after a `+` EPC built with a small encoder (key qualifiers to the path, data attributes to the query string, every Table F method), `++` hostnames (URN Code 40, 7-bit with the optimisation tables), refusals, RE3, the TDT artefacts against their JSON schema and Table B. With `EPC_TDS` set to a directory where `npm install epc-tds` was run, 800 random EPCs of eight classic schemes are compared with that independent library. | `pip install jsonschema`, then `python dev-tests/resolver/test_epc_binary.py` |
| `resolver/test_data_entry_api.py` | The **data entry API**: token protection — every operation except `/heartbeat` returns 401 without a token and 403 with a wrong one (including `/index` and `/summary`), and the Swagger description declares `BearerAuth` on each of them. Also the **registration rules** of GS1-Conformant Resolver 2.5.9 on `POST /new` and `PUT` (qualifiers per key, 415 needs 8020, 235 alone, no 22 or 10 with 21; a list refused whole) and **`informativeQualifiers`** (stored, returned, listed by `/summary`, replaced, kept or cleared by `PUT`, refused outside a serial number). | `pip install -r data_entry_server/src/requirements.txt`, then `python dev-tests/resolver/test_data_entry_api.py` |
| `portal/test_portal_config.py` | **Portal start-up configuration**: public address from `RESOLVER_PUBLIC_URL` or `FQDN`, Secure cookie default, first user from `PORTAL_ADMIN_*` only while the store is empty. | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_portal_config.py` |
| `portal/test_registration.py` | The **registration model of GS1-Conformant Resolver 2.5.9** through the portal's API: a serial number saved with its serial only and its variant and batch as informative qualifiers (opened, history, record list, export and import again, a changed batch in the import preview), records against rule 2 flagged, qualified records of keys without a record of their own flagged, the key's own record created when saving (`keyRecord` copy or target) and when importing (`createKeyRecords`). | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_registration.py` |
| `portal/test_keys.py` | **Primary identification keys and key qualifiers** (URI Syntax 4.3-4.9): valid and invalid values of every key and qualifier combinations, and — with `GS1_SYNTAX_ENGINE` pointing to a folder where `npm install gs1encoder` was run — agreement with the GS1 Barcode Syntax Engine that the resolver uses. | `pip install -r portal/requirements.txt`; optional engine: `mkdir -p /tmp/se && cd /tmp/se && npm init -y && npm pkg set type=module && npm install gs1encoder`; then `GS1_SYNTAX_ENGINE=/tmp/se python dev-tests/portal/test_keys.py` |
| `portal/test_governance.py` | **Governance** through the portal's API: roles, GS1 Company Prefix limits, user administration, temporary passwords, last-administrator and self-lockout protection, history of a record, audit trail and CSV, conversion of a users file from before roles. | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_governance.py` |
| `portal/test_sheet.py` | **Spreadsheet** reading and writing: CSV with `;` in Windows-1252 and Portuguese headers, canonical keys, GTIN in scientific notation, yes/no values, conflicting descriptions, missing columns, size and format errors, row and size limits of each format (`sheet.FORMATS`), XLSX and CSV round trips. | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_sheet.py` |
| `portal/test_data_attributes.py` | **GS1 Digital Link data attributes**: the GS1 Barcode Syntax Engine and dictionary release, the AIs offered (ranges expanded, (8200)/(03)/(8014) excluded), URIs built with attributes (SSCC with content, count and batch; percent-encoding), every refusal of the portal and of the engine (dates, associations, invalid pairs, CSET 82, length), one engine shared by threads, the API (`/config`, `/digital-link`, `/qrcode?attr=`, prefix check, sign-in), QR codes decoded, day 00 refused, decimal families (comma or point, members, currency prefix, every refusal), label options (HRI modes, forced QR version and level, too small or too long content, invalid options), and the portal without the engine. | `bash portal/tools/build-syntax-engine.sh /tmp/gs1se`, then `GS1_SYNTAX_ENGINE_DIR=/tmp/gs1se python dev-tests/portal/test_data_attributes.py` |
| `portal/test_special_chars.py` | **Special characters**: other scripts' digits refused in every key, qualifier, language tag and prefix (never an internal error), invisible characters removed from identifiers, descriptions and titles in NFC without control characters, addresses with spaces, line breaks, backslashes or invisible characters refused, XLSX exports without formulas, CSV exports protected against formulas and read back unchanged, UTF-16 text files, typed user names in the log and audit CSV. | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_special_chars.py` |
| `portal/test_linkcheck.py` | The **link checker** against a local HTTP server: 200, 404, 500, 403 (blocked), HEAD refused → GET, redirects, endless redirects, closed port, unknown domain, HTTPS → HTTP detection, cache, parallel checks with progress, refusal of internal addresses (loopback, private, metadata service). | `pip install -r portal/requirements.txt`, then `python dev-tests/portal/test_linkcheck.py` |
| `portal/test_portal_e2e.py` | The **portal** in Chromium against `mock_data_entry.py`: sign-in, check-digit feedback, create with default link (no query-string option), live language switch, labels (PNG decoded, SVG), user menu, informative batch and variant of a serial number (marks, *This record applies to*, stored values filled in, differences pointed out), the dialog offering the key's own record when saving a batch, *Copy targets from…*, confirmation before discarding unsaved changes, the *Status* filter and alert, record list (search, filter, open in editor, history), spreadsheet export → edit → import (preview, confirmation, result), link checker (editor, every record, import preview), password change, sign-out. | `pip install -r portal/requirements.txt playwright opencv-python-headless && playwright install chromium`, then `python dev-tests/portal/test_portal_e2e.py` |
| `home/test_home.py` | The **home page**: the real `frontend_proxy_server/nginx.conf` in a local nginx against mock upstreams (`/`, `/home/` assets and redirects, and every other path still reaching the resolver, data entry API and portal) and the page in Chromium (menu links, root-relative links, pt-BR/en-GB, resolver root from the address bar, operator from the description file, phone menu, no CSP violations, no-JavaScript fallback). | nginx on the PATH, `pip install playwright && playwright install chromium`, then `python dev-tests/home/test_home.py` (screenshots in a temporary folder, or in `HOME_TEST_SCREENSHOTS`) |

| `install/test_install.sh` | The **installer** in eight scenarios (fresh Let's Encrypt, re-run, hand-written `.env` on an existing installation, own certificate, external proxy, interactive answers with invalid input, refusals, proxy left pointing at recreated services) with stand-ins for apt-get, systemctl, docker, certbot and curl; the written `.env` is checked with the real `docker compose config` and the nginx site with the real `nginx -t`. | Linux, root, nginx, openssl and a Docker Compose v2 binary (`COMPOSE_BIN`, default `/tmp/docker-compose`), then `sudo dev-tests/install/test_install.sh` |

`resolver/linkset-schema.json` is a copy of https://ref.gs1.org/standards/resolver/linkset-schema.
`resolver/description-file-schema.json` is a copy of https://ref.gs1.org/standards/resolver/description-file-schema
(version 1.2.0).

The upstream integration test `tests/setup_test.py` needs the full stack running (`docker compose up -d`)
and reads the API token from `SESSION_TOKEN` (default `secret`, as in `.env.example`).

`docs/screenshots.py` is not a test: it produces the screenshots of the top-level README
(`Documentation/images/*.png`) and of the portal user guide in English (`Documentation/images/guide/*.png`)
and in Portuguese (`Documentation/images/guide/pt-BR/`) from the real portal and home page with example data, hiding the GS1 logo; run it again after visual changes
(`pip install pillow playwright`) and commit only the images that really changed.

**GS1 Barcode Syntax Engine for data attributes.** The portal validates GS1 Digital Link data attributes
with the engine's native library, built by `portal/tools/build-syntax-engine.sh` (needs `curl`, `make` and
a C compiler) exactly as the portal image builds it. Set `GS1_SYNTAX_ENGINE_DIR` to the build directory
when running `test_data_attributes.py` (required), `test_portal_e2e.py` (the data attribute steps run only
with the engine; without it the test checks that the option is hidden) and `docs/screenshots.py` (writes
`portal-attributes.png` only with the engine). The other tests do not need it.
