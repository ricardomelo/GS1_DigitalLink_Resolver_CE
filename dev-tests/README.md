# Development tests

All run without Docker or MongoDB and exit with status 1 on any failure. Run them from the
repository root.

**The portal's database.** The portal keeps its data in MongoDB (`portal/store.py`). The portal programs
set `PORTAL_DB_URI=mongomock://` (an in-memory stand-in: `pip install mongomock`) and a database name of
their own, unless `PORTAL_DB_URI` is already set: then they run against that MongoDB, each in its own
`devtest_*` database. Only `test_store_mongodb.py` and `test_worker_processes.py` need a real server.

**The portal's job worker.** Imports, link checks and e-mail messages are jobs run by a worker
(`portal/worker.py`). The programs that run them set `PORTAL_WORKER=embedded`, so the portal starts its own
worker thread; `test_jobs.py` drives workers itself, and `test_worker_processes.py` starts `worker.py` as
processes.

**E-mail.** `test_mail.py` sends to an SMTP relay of its own (`dev-tests/portal/fake_smtp.py`, on 127.0.0.1 and a free
port, with a certificate made by the `openssl` command); no real relay and no network are needed.

**Through pytest.** `test_programs.py` runs every program above as one pytest test, from the repository
root, and `conftest.py` keeps pytest from importing the programs themselves. A program passes when it exits
with status 0 and prints no `FAIL` line; a failure shows its `FAIL` lines and the end of its output; a
program that only printed `SKIP` is skipped. The number of checks of each program is printed at the end.

```bash
pip install pytest
python -m pytest dev-tests                            # every program; those missing a piece are skipped
python -m pytest dev-tests -m "resolver or portal"    # groups: resolver, portal, e2e, home, install, database
python -m pytest dev-tests -k gs1_suite               # one program (ids as in PROGRAMS)
DEV_TESTS_STRICT=1 python -m pytest dev-tests         # missing variables, commands or SKIP lines fail
```

Groups: `resolver` = `test_resolver`, `test_gs1_suite`, `test_epc_binary`, `test_data_entry_api`; `portal` =
the portal programs without a browser; `e2e` = `test_portal_e2e.py` with the engine and without it
(`GS1_SYNTAX_ENGINE_DIR=/nonexistent`), `test_session.py`; `home`; `install` = `test_install.sh` (through `sudo -n` when not root; `PATH` and
`COMPOSE_BIN` are passed on) and `test_deploy.py`; `database` = `test_store_mongodb.py` (needs
`PORTAL_TEST_MONGO_URI`). `DEV_TESTS_TIMEOUT` (seconds, default 1200) limits each program.

**Continuous integration.** `.github/workflows/dev-tests.yml` runs one job per group on GitHub Actions on every
push and pull request to `gs1br/develop`, with `DEV_TESTS_STRICT=1`; the job `database` starts a `mongo:7`
service container and runs the `portal` and `database` groups on it (`PORTAL_DB_URI` and
`PORTAL_TEST_MONGO_URI` set to it); `database` is informative (`e2e` and `install` were too, until step 4 of
item 2.3). `.github/actions/dev-tests-setup/action.yml` prepares the runner and holds every pinned version
(Python 3.12, Node.js 24, `gs1encoder` at the release of `docker-compose.yml`, `epc-tds` 1.4.1, `ajv-dist` 8.17.1, GS1's suite at `32597c1`,
Docker Compose v2.29.7, nginx 1.30.5 from nginx.org for the `home` job); the engines, npm packages and Chromium are cached. The check counts of each job are on the
run's summary page.

`resolver/linkset-schema.json` is a copy of https://ref.gs1.org/standards/resolver/linkset-schema.
`resolver/description-file-schema.json` is a copy of https://ref.gs1.org/standards/resolver/description-file-schema
(version 1.2.0).

The upstream integration test `tests/setup_test.py` needs the full stack running (`docker compose up -d`)
and reads the API token from `SESSION_TOKEN` (default `secret`, as in `.env.example`).

`docs/screenshots.py` is not a test: it produces the screenshots of the top-level README
(`Documentation/images/*.png`) and of the portal user guide in English (`Documentation/images/guide/*.png`)
and in Portuguese (`Documentation/images/guide/pt-BR/`) from the real portal and home page with example data, hiding the GS1 logo; run it again after visual changes
(`pip install pillow playwright`) and commit only the images that really changed.

**GS1 Barcode Syntax Engine for data attributes.** The portal validates GS1 Digital Link data attributes
with the engine's native library, built by `portal/tools/build-syntax-engine.sh` (needs `curl`, `make` and
a C compiler) exactly as the portal image builds it. Set `GS1_SYNTAX_ENGINE_DIR` to the build directory
when running `test_data_attributes.py` (required), `test_portal_e2e.py` (the data attribute steps run only
with the engine; without it the test checks that the option is hidden) and `docs/screenshots.py` (writes
`portal-attributes.png` only with the engine). The other tests do not need it.
